# 007-E1 缩略图只读试算

E1 提供独立的 Linux 命令 `preview-cache-trial`。输入是已封存的 C 账本备份和指定的预览缓存目录。默认模式下，账本里有引用只证明该引用曾被登记，空结果也只能证明快照里没有行。两种情况都没有物理删除资格。合成证据可以演练确认、宽限及共享对象保护。报告里的 `executable_deletes` 固定为 0。

## 分类和证据

| 分类 | 最小证据与处理 |
| --- | --- |
| `valid_referenced` | 合成观测确认来源版本有效，观测时间不早于发布。SQLite 中有同 asset、位置、版本的精确引用，预览存在且大小一致。`last_used_at > 0` 单列为有过前台使用记录。 |
| `version_retired` | 合成观测确认该发布版本无法继续命中，覆盖到其他共享引用。账本快照中该 asset 无引用，移动状态已完整检查。 |
| `no_reference` | 合成观测提供完整范围的最后引用失效事实和时间。同样检查账本、共享物理键和移动状态。确认与宽限到期是两项条件。 |
| `uncertain` | 仅有账本引用时，父目录身份和文件名无法反推当前可达源路径。空引用、离线、身份变化、权限不足、扫描不完整、索引过期、移动待定或歧义均保留。两个移动端点的资产都受保护。 |
| `file_missing` / `size_mismatch` | 只报告当前缓存一致性。缺文件可释放量为零。大小异常不能证明原发布已退役。 |
| `unattributed_hash` | 完整账本里找不到物理键。旧缓存和原子写完成后未发布的文件可能外观相同，保留两种解释。部分账本的未匹配对象只记为 `unattributed`。 |
| `temporary` / `unregistered_publication` | 前者识别同目录 `.preview-*` 临时文件。后者只在合成观测明确指认且完整账本仍无该键时单列。两类均无估算回收量。 |
| `skipped` | 符号链接、嵌套挂载、权限失败、非普通文件、字节超限或目录读失败均有原因。已知缓存布局之外的条目排除。 |

确认版必须绑定 asset、variant、storage key、大小、摘要和 `generated_at` 组成的发布身份。合成宽限取 7 天，从已确认观测时间算起。共享物理键有任一受保护发布、任一引用仍存在、移动覆盖不足、扫描未覆盖完整结果表或存在硬链接，均阻止物理量估算。估算前读取该合成候选的有限缓存字节，核对摘要和同一 inode 的版本。真实账本缺少可信的失效事件、全范围观测代次、发布占用及宽限记录。命令的 `-fixture-evidence` 接受人工构造的声明，仅用于合成测试。

## 从账本行到报告

1. 命令从封存备份按 `results.rowid` seek，每行通过 `refs_asset` 索引判断该 asset 是否有任意引用。存在一份即可保护所有变体，无需逐条遍历高扇出的引用。合成正向观测再用 `(source,path)` 主键核对精确行。移动查询分别用 `moves_pending` 约束 pending 和 ambiguous。已完成的移动不占该预算。查询计划在复跑日志中。
2. `diskcache.RelativePath` 使用与常规 I/O 相同的算法，将实际 storage key 定位到 `diskcache/<1 hex>/<2 hex>/<40 hex>`。以 fd 固定专用根。Linux `openat2` 拒绝符号链接和根下所有挂载穿越，包括同设备 bind mount。缓存父目录和根本身也拒绝符号链接。目录用无 atime 方式打开。命令只读普通文件的属性，合成候选摘要验证除外。
3. 报告按物理键汇总同一窗口内的全部发布，按设备和 inode 去重。账本 `recorded_row_bytes` 是纳入预算的行大小之和，允许同对象的多行各记一次。物理 `unique_logical_bytes` 按 inode 一次计 `st_size`，`unique_allocated_bytes` 一次计 `st_blocks × 512`。行数与物理名称数是不同口径。跨类共用的 inode 可能分别进入类别小计，总计单独去重。部分窗口之间也可能重复观察 inode，不能相加当全局去重值。稀疏、压缩、reflink、文件仍被打开、权限失败或文件变化都影响实际释放量。`partition_available_bytes` 来自根 fd 的 `f_bavail`，是整个文件系统当时的可用量。
4. 报告记录查询窗口时间、SQLite 备份身份、覆盖标记和跳过原因，样例只含哈希 ID。命令唯一的输出是 stdout JSON 和错误时的 stderr。它不启动服务器，不打开应用的账本写入口，不更改引用、移动、访问时间字段、预览文件或来源。SQLite 读取普通备份文件时，系统可按挂载策略更新备份的文件访问时间。

## 快照、分页和限制

SQLite 输入由维护者单独从在线备份 API 或 `VACUUM INTO` 生成，使已提交的 WAL 页进入一致副本。封存独立副本后才传给命令，副本必须采用 DELETE 日志页头，且不存在 WAL、SHM 或 rollback journal。读取用 `mode=ro&immutable=1`，开始和结束核对文件身份、大小、mtime、ctime 和 sidecar。直接复制热库的主文件不可作为输入。试算不会生成备份。备份和磁盘观察之间没有原子边界，静止缓存或外部一致快照可以改善可比性。运行中可能出现发布、替换或移动，以报告的观察窗口解释结果。

结果游标绑定同一备份的 `snapshot_id`。目录按文件系统在静止目录提供的 `getdents64` 顺序逐页读取。游标保存最多三层目录身份、时间戳和继续位置，恢复时检查仍打开的各层。已走过的分支可能再发生变化，跨页汇总必须使用静止的缓存。`next_cache=done` 表示目录读至末尾，后续页传回它可跳过目录。目录可续跑需要支持可寻址目录 cookie 的 Linux 文件系统，运行要求 Linux 5.6 以上和缓存进程用户或有 `O_NOATIME` 权限的用户。

对结果、移动、目录各自限条目数，账本行字节、账本窗口观察的物理逻辑字节、目录物理逻辑字节各有限额。单对象超额记为跳过并推进游标。多对象累计到上限则从该对象前继续。SQL 额外读取最多一条判断触顶，目录只有三块 8 KiB 读取缓冲区。对象表和分类样例受条目上限约束。SQLite 和遍历共用超时及取消上下文，阻塞的内核文件系统调用可能延迟退出。目录名排除和实际读取失败均计入报告。没有完整结果覆盖时，跨窗口共享键和未归属分类仍不确定。超过硬上限的大账本可逐页查看已登记结果和目录，E1 不提供跨页全局关联。复跑时可独立提高各限额或跳过已结束的目录窗口。

## E2 接线与恢复草案

现有 `DelThumbs` 用路径、大小、mtime 计算旧键，通常只尝试 small，因为 Delete 对不存在的键也返回成功。large 只在 small 删除报错时尝试，xlarge 和其他参数未覆盖。普通单删在磁盘删除前调用。废弃公开单删、两种批删在成功项后调用。普通和分块上传覆盖在确认 override 后、写入或组装成功前调用。C 的同盘移动在成功路径调用 `DiscardMovedLegacy`，仅照顾旧格式。目录 rename 通过父目录身份保留 C 定位，C 的后台恢复分页处理 pending 和 ambiguous 并修复账本状态。其恢复不调用旧键删除。E1 保留这些时序和行为。

E2 在成功提交删除、覆盖和移动的实际条目后更新失效事件。目录删除按原目录身份及组件边界分页，部分成功只确认有证据的项。外部扫描必须有范围、来源身份和完成代次，离线、降级和 F 的待匹配关系继续保护。最后一份引用离开才开始宽限。前台现有路径是定位、查引用、防并发生成、编码、同目录临时写和原子 rename、账本 Publish、成功前台交付后 Touch。D 同样先写文件，再核对源并 Publish。C 移动另外经过短位置锁、SQL 意图、文件 rename 及收尾。SQLite 事务无法和缓存文件 rename 或 unlink 原子提交。

拟为每次发布使用持久的发布 ID，并在 asset 引用及物理键层建立共享协议。E2 在短事务核对同键各发布、所有引用、年龄、移动或恢复中的资产，预留带发布 ID 的回收意图。引用恢复、前台读取、同键生成与移动必须走同一协议。当前 `FileCache` 的写删条带锁只保护磁盘步骤，须把预留检查及发布完成连接起来。建议为缓存根指定单一写入者，并以进程间机制拒绝第二个写入者。位置锁与键锁的顺序需写成实现约定，持锁时间不含解码。回收复查根、键、inode 和发布 ID 后在同挂载下隔离旧文件，使用不会覆盖另一对象的原子 rename，再分批 unlink 并记账。读者和正在生成的键在成功隔离前受保护。新引用可撤销预留，或依发布身份恢复隔离的旧对象，遇到更新发布时保留更新发布。

恢复按意图和当前文件状态重放。预留后未移走可以重新复查或取消，已隔离未 unlink 可以重查引用和新发布，已 unlink 未记账可以按意图补账。删除失败记原因、退避和进度。“写好未登记”须核对生成意图和当前引用，决定完成发布或保留待修复。既无意图又无法归属的旧文件继续保留。审计分别记候选、实际 unlink、估计释放和失败。范围只含缓存派生文件。图片本身及尺寸、比例、方向元数据单独保留。

## E3 接线草案

`previewwarmup.Worker.step` 在查询 D 的候选前调用 `resourceProbe.poll`，当前 Linux 门槛含 512 MiB、32 个 inode 和只读挂载检查。容量状态可接在此处和 `process` 的解码准入回调。发布还需在写临时文件前按实际生成大小核对剩余空间和并发预留，给前台保留空间。初始实验可按容量上限的 90% 暂停 D、75% 恢复，按实际余量 512 MiB 暂停、768 MiB 恢复，并要求持续 60 秒且逐步释放后台槽位。此组值是待测假设，需在限额容器及有代表性的分区波动中验证后再定真实启用值。

D 的索引 guard 仍表示该索引版本曾处理。准备独立的 asset、variant、发布 ID 级冷却记录，区分已完成、容量淘汰、未生成或损坏缺失。跳过冷却中的后台补齐，不清空所有已完成 guard。前台显式访问正常按需并受预算和实际空间准入约束。可先试 24 小时冷却、新生成保护 1 小时和近期访问保护 7 天，先回收到期孤儿和退役结果，再按配置从未用于前台的有效预览开始，最后考虑长期未用对象。压力不缩短孤儿宽限。默认无年龄 TTL。为 D、孤儿回收、容量淘汰分别提供开关和可观测暂停/恢复原因。后续需验证重启、读写竞争、配额和前台恢复。
