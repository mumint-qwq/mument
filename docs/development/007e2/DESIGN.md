# 007-E2 确认孤儿后的回收

E2 的父提交为 8ee0efd66b0ea3367a4575cea114c37861e5fc26，树为 0d3522fc3ed61f5474cc3f86fc8039ffd9c19247。工作树位于 mument 相邻的 worktrees/007e2-orphan-reclamation，分支为 feature/007e2-orphan-reclamation，由维护者指定从通过复审的 E1 候选开始。

Linux 服务取得专用缓存目录的写入租约后可以登记新发布及失效事件。server.previewOrphanReclamation 默认 false。关闭时没有定时执行、隔离或删除，持久意图和隔离文件保留。管理员 GET /api/settings/preview-orphans 返回有界试算、宽限及拒绝原因。E1 的封存试算可以独立运行，其输出不参与执行。

## 从文件操作到候选

| 产品入口 | 可信提交点 | 保留边界 |
| --- | --- | --- |
| 认证和分享单删、批删、归档后删除 | 共用 files.DeleteFiles。先固定旧文件身份。磁盘操作成功，旧 inode 失去一个链接且旧名称消失时，按精确旧引用登记。索引刷新在后。 | 权限失败、删除失败、同名身份变动、账本繁忙均保留未证实项。批删逐个成功项独立处理。 |
| 小目录删除 | 描述符遍历同挂载最多 32 项、8 层。核对待处理文件仍可从固定目录访问。完整删除后核对存活的父目录、已移除的目录和每个旧 inode 的失链。 | 部分删除、跨挂载、符号链接、扫描中断或超限均保留未证实后代。 |
| 普通写入及编辑器保存 | POST 普通覆盖、PUT、公开 PUT 和 OnlyOffice 通过 files.writeFile。在截断前核对已打开文件的旧版本。完整写完、close 成功且原路径仍指向该 inode 的新版本后确认。 | 写失败、上传中断、同名替换和来源符号链接均保留。普通原地写仍沿用既有失败契约。 |
| 直传、分块覆盖与 C 同盘操作 | 完整数据经 files.MoveResource rename。确认旧目标 inode 失链且最终目标是已观测的传入对象。C 已转移引用时，另外核对已完成意图中的旧目标。 | 临时写、失败分块、跨盘复制回退、pending 或 ambiguous 意图均保留。同盘移动本身复用缓存。 |
| WebDAV | filteredFileSystem 独立使用 x/net/webdav。实际删除验证了它绕过 DeleteFiles，写入和 rename 同样独立。 | WebDAV 的 DELETE、PUT、COPY 和 MOVE 继续保留无法确认的账本引用及缓存。 |
| 旧键与外部变化 | DelThumbs 保持既有旧键优化。 | 老版本零引用、未登记写入、外部变化和 E1 样本均无执行证据。 |

操作前存 pending 事件。成功后，同一短事务按来源、位置、asset 和旧版本撤销对应引用、确认事件，再核对最后一份引用。触发器记录未经证明的删除或替换。C 已证实的引用转移和 E2 成功操作才撤销对应标记，普通 Resolve、Detach 和移动恢复留下的缺口保持保护。数据库故障或进程退出留下 pending 供对账。

目录遍历、递归删除和删除后的 inode 检查都在全局位置锁外。超限目录直接走原有删除路径。小目录只在登记和确认旧引用时分两段短暂取锁，每段证据处理的协作预算为 250 ms，最多处理 32 项。期间移走、重建或替换的引用仍受旧版本和精确位置约束。单文件持锁期间使用非递归删除，路径类型过期时递归回退也在锁外。

最后一份引用确认离开，且没有未证实引用损失或挂起移动时，记录资产级确认及宽限截止。随后还要核对整个物理键的所有发布。默认 168 小时，给纠错留一周。server.previewOrphanGraceHours 可为 24–8760，仅影响随后确认。恢复引用取消候选，再次确认最后一份离开才重新计期。实际执行还检查持久时钟高水位，回退时等待追平。

## 物理执行和恢复

1. 前台读取、前台 Store 到 Publish、D Store 到 Publish 与执行器共用固定物理键条带。先取键门，再取 C 位置门，再进短 SQL 事务。解码在锁外。首次摘要校验释放位置门，随后重新取得并复查。恢复中的单文件摘要读取可能短时阻塞位置门。
2. 新发布在 C v1 的辅助表绑定随机 epoch、缓存根、对象 inode 和创建时间、大小、mtime、ctime 及分配块。旧 C/D 发布缺少该物理证明，继续保留。旧 D 重发同一结果时触发器撤销旧标签。
3. 执行通过索引核对最多 16 个同键发布及其全部引用、未证实损失和移动意图。复查配置中的来源和目录身份。openat2 限定描述符下的专用 diskcache，拒绝符号链接、嵌套挂载和硬链接。在 64 MiB 预算内验证摘要。
4. 在锁下写入 reserved。在允许隔离前先持久化 moving，随后以 RENAME_NOREPLACE 隔离原文件并同步目录。校验隔离 inode 后持久化 isolated。重查来源后 unlink 隔离名并同步目录，再持久化 removed 和结算。结算只删除匹配该 epoch 的缓存发布。审计以匿名物理对象 ID 记逻辑大小和 st_blocks × 512，实际释放取决于文件系统、reflink 和外部打开句柄。
5. reserved 说明移动尚未开始。moving 重启后根据原路径和隔离路径识别旧对象。isolated 可复查继续。隔离文件已缺失且未记录 unlink 时只记 missing_after_isolation 和零字节。引用回来了且原发布匹配就尝试无覆盖归还。写好未登记的缓存仍保留。关闭执行器时冻结这些意图。
6. 意图以物理键及发布 epoch 集合共同领取。新发布出现后，旧 reserved 且其隔离名确实缺失时，以 superseded_reservation 和零字节结束。旧发布已进入或可能进入隔离时，以旧 ID 保留 held 和隔离文件。新发布需按自身最后一次失去引用的时间达到宽限，使用自己的意图结算。迁移旧 E2 意图时保留原行号及隔离名，将旧 reserved 视作可能已移动。

写入租约用真实目录 inode 的 flock，路径别名也争用。启用要求显式持久 cacheDir、关闭旧缓存目录清理，并由服务用户独占写入。旧版 D 和外部进程不遵守此租约，升级及回退需要顺序停启。缓存根和来源使用已知文件系统类型、非零文件系统 ID、设备号、inode 和创建时间进行持久比对。目前接受提供这些字段的 EXT4、XFS、Btrfs 和仍存活的 tmpfs 实例。挂载 ID 仅用于本次运行。重启后重新打开根和父目录，核对持久字段，再用当前挂载边界限制访问。设备号变化、磁盘或对象替换、旧证明缺少创建时间，以及无法可靠识别的卷均保留。状态会给出身份变化或持久身份不可用的原因。持久字段无法区分由特权操作完整复制全部标识并替换原设备的副本，执行前的单写者和受控挂载要求仍适用。

每分钟最多一个执行窗口。每窗至多 16 个意图和 16 个候选对象，单文件 32 MiB，验证载荷总计至多 64 MiB，共用 2 秒协作取消。内核阻塞调用可能延迟退出。状态包含候选、意图和匿名对象续页位置，每类审计和样例限 16 条。首次启动会为现有账本建立辅助索引。回退前关闭并排空 E2，再按持久意图核对隔离文件。D 可以读取原 v1 表和仍有效的缓存，B 的比例、尺寸和方向及 D guard 继续由各自索引管理。

E3 的水位可接到候选领取和落盘准入，容量淘汰及 D 的冷却独立于 E2 的孤儿宽限。F 的外部和跨盘关联留待后续。
