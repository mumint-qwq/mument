# 007-E3 缓存空间协调

E3 基于本地 main 合并提交 e425444bd7979467376e18b0a88c752ec0538e2c。独立分支为 feature/007e3-cache-space-budget，基线文件树为 c07cd707545496c8617b8f4b563d5250dfa9a8d8。

## E3-1 空间观测与准入

未配置 server.previewSpace 时沿用 E2。observe 提供真实分区与专用目录观察，不限制发布或 D。enforce 使用相同统计限制发布，按水位暂停 D。容量淘汰另设 capacityEviction 并默认关闭。需要显式持久 cacheDir，关闭 cacheDirCleanup。生产没有预设的专用目录容量，示例数值用于合成测试。

- 每秒检查当前租约根的 statfs。按可用块和分配单元换算可用字节，另报可用 inode、只读、根和运行时挂载身份。其他文件、缓存和数据库会影响分区读数。
- 物理库存以有界描述符遍历观察 diskcache 内的普通文件，包含受保护旧文件、隔离区和残存临时文件，按 inode 合并硬链接。目录、文件系统元数据和其他缓存目录计入分区压力。遇到不可访问、挂载边界或遍历上限时报告覆盖缺口。专用目录之外的旧散列目录保持原位，其占用由分区读数反映。
- 启动、状态请求及前台命中不扫描。单次后台库存以 512 项或 20 ms 协作窗口推进，最多 12 层、65,536 个多链接 inode。全量验证结束才能替换观测，受控写入跨窗口时重试，周期性重扫外部变化。过期或缺覆盖时，enforce 保留有效命中并停写，已有编码结果可直接交付。
- 默认停线为预算 90%、实际余量 512 MiB 或 32 inode，复位需要低于预算 75%、实际余量达到 768 MiB 且至少 64 inode，持续 60 秒。无可用 inode 计数的文件系统仍以真实写入错误兜底。D 保留已有的 cgroup、最低资源、前台和来源检查。普通、近期和手工入口先看公共水位，解码和写入前复查。
- 编码后进入共享预留，按实际分配单元上取整，预留同分区目录开销及在途 inode。前台可用到预算硬线和最小余量。后台写入再保留预算的最后 10% 和复位余量。临时文件与旧版本共同占用，替换和保守计数在完整核对时释放，状态标出包含写入调整的估算。受控发布使用租约根下描述符，刷新分片和根身份后提交，不跟随符号链接或进入嵌套挂载。
- 缓存命中不进入准入；前台存盘受限只对本次交付有效且已经过版本核验的编码字节。同一个共享任务的 D 等待者接收原空间拒绝，保留游标和尝试预算。真实 ENOSPC、EDQUOT 和 EROFS 触发核对，临时对象由写入路径逐次清理。

管理员 GET /api/settings/preview-space 读取当前快照、覆盖、在途预留、D/E2/E3 开关和前台未落盘数。配置变更在受控重启时生效。普通 D 管理入口可立即暂停或恢复 D。

## E3-2 容量窗口与隔离

持续压力先给已启用的 E2 一个有界窗口，沿用原分页、原宽限和原关闭状态。执行后重读分区读数，发生物理删除时等待完整库存再决定是否需要容量淘汰。E3 使用真实压力和已核对的库存。过期、调整中或缺失的库存不作为高占用删除理由。空间回升时可安全归还与当前发布身份一致的隔离对象。

候选索引只包含 E3 已观察到来源证明的发布。先按生成时间检查至少存放一小时、从未给前台成功使用的变体，再按实际使用时间检查至少七天未用的变体。每页至多 16 个键、64 MiB 摘要和 2 秒协作预算。候选发布的源根和原文件必须一一对应当前强引用。缺少来源证明、多个引用范围、挂起移动、未证实损失、旧散列及未知文件均保留。已有 E2 结果可以继续命中，等待通过可信发布建立 E3 证据。

前台在第一次读之前登记占用，直到交付和合并使用记录结束。回收按物理键、位置门及短 SQL 事务顺序检查；验证摘要释放位置门。容量与孤儿共用有租约根、隔离、物理身份和恢复协议。容量意图和审计使用独立的表，旧 E2 不会领取这些意图。结算只撤销该发布的结果，保留图像引用、asset 及 B 的元数据。

管理员 GET /api/settings/preview-capacity 试算一页，即使容量淘汰关闭也可观察候选，试算不回收。分页传回 next 中的 time、row、used 和 intent。POST 同一路径用 {"action":"pause"} 和 {"action":"resume"} 暂停或恢复已启用的容量执行器；正在完成的有界窗口会在下一次保护检查读到暂停。关停并冻结隔离前先通过状态核对未结项。

## E3-3 冷却、重建和回退

容量账本在旧 epoch 的结果确实移除后，按 asset、变体、被淘汰 epoch 及原因登记 24 小时冷却。进程在 unlink 后退出且实际字节无法归属时，审计记零字节，但已不存在的旧结果仍可产生冷却。未移动的预留或已经归还的对象没有冷却。新的成功发布在同事务结束对应冷却；有效字节只在本次内存交付时保留冷却。

D 先复用有效命中，再核对冷却和正在恢复的容量意图。自动、近期和手工入口对同 asset、同变体统一跳过；D 的完成 guard 仍表示曾经处理此版本。一个受控同盘移动可以继续使用原 asset，因此不会逃过冷却。新原图版本和不同变体具有不同身份。低水位连续稳定后，D 最多每个范围五秒从有索引的到期页领取一项。先核对源根、文件版本和当前索引，再进入 D 的空闲及资源准入。旧路径无法反向定位时等待后来发现或手工访问。

enforce 将缓存根持久身份固定在同一账本中。进程重开会重新核对当前根；换卷或换目录时暂停写和容量处理。现有符合摘要的前台读仍可交付，身份不明时不撤销旧结果。更换专用缓存时使用维护者核验后的独立 cacheDir 和账本。容量与 E2、D 均可独立停用。部署按 E2 的单写者规则顺序停启。

回退时保留 SQLite、专用缓存和索引。旧 E2 和 D 忽略容量意图区及冷却，能读取未淘汰预览，也能按请求生成已淘汰变体。旧版本的 D 不承诺遵循 E3 冷却。已隔离的容量意图仍由 E3 核对；新字节会因发布身份不同而保护。回到 E3 后已有有效新命中优先于旧冷却，避免再解码。读取旧版本已写的元数据不需要用备份覆盖数据库。

## 异步观测边界和走读

- 一次前台请求先完成 C 的版本计划。现有真实命中仅记录合并后的实际交付。未命中由 A 合并同键任务，核对读到的原图身份和现有路径。编码后申请空间，暂存成功才发布账本。预算不足交付已确认有效的字节，并在状态计数。
- 一次 D 领取先检查空间状态，再通过既有 CPU、内存和来源保护。即使是管理员手工补齐，也要等待恢复线稳定。缓存已经可用时直接确认，冷却时保留 guard 并推进游标，写入时留下前台余量。
- 一次预算或余量触线会暂停 D。若 E2 开启，先进一轮到期孤儿处理。复测仍有压力且容量开关打开时，当前冷结果通过引用、前台使用、最近发布、根、摘要及物理身份复查后隔离和移除。没有安全候选时继续暂停。
- 库存是有时效的观测。受控并发写入会使扫描代次失效。文件系统上未经协调的外部变动可能在两次库存间出现，实际分区余量仍按 statfs 采样，保守旧占用由周期复核纠正。管理值需要为其他使用者、文件系统元数据及 CoW 留出余量。占用和分配块都不承诺等于实际回收后分区可用量。
