# 007-D idle mosaic previews

The worker is opt-in on Linux. Each configured scope names an indexed source and a clean relative directory. Mounted libraries can require a specific source-relative mount point, including the source root. The existing host media guard remains the deployment-time UUID check. The worker checks index readiness, component containment and live directory/mount identity. Descriptor-relative opens reject symlinks and nested mounts below the scope. A read uses the verified regular-file descriptor. The indexed B version and C version are checked around the read and the live path is revalidated before publication. A different mount or directory identity during a task invalidates that task.

A single worker rotates through configured scopes. Every second turn uses a path cursor in that scope; other turns can favor the last directory observed by foreground preview and newly indexed versions. Index seeks return at most 16 rows. Two opt-in partial indexes cover outstanding JPEG and PNG versions by path and observation guard. Per-row completion and bounded retry fields are keyed to the existing version guard. Their storage is bounded by the index itself. The cursor can be recovered from the beginning after restart because completion is committed per version, independently of path order. Cache publication precedes completion, so a crash in that gap rechecks the existing result. Completed rows leave the selection indexes. Manual fill makes one bounded pass in a configured scope and also checks completed rows. A rebuilt index can recover by checking the same ledger, and earlier versions ignore the added index columns.

The worker reuses C's variant identity, cache and publication, A's preview flight and budget, and B's strong version. A cache presence check uses only ledger data and file metadata. Read-only reference lookup precedes header admission so skipped originals and rejected headers allocate no ledger asset. The cache uses fixed lock stripes for atomic stores and deletes as the number of warmed keys grows. Foreground reads continue to verify cache contents. Small originals use the existing size or dimension rule. Background decodes accept bounded static JPEG/PNG headers and use the in-process raster path with external fallback disabled. One background flight never queues in the decode FIFO. Foreground callers sharing a background flight retry through ordinary admission when background work defers or fails. A decode already in progress retains its reservation through completion. A source guard failure at publication defers an offline or unready scope and sends joined foreground waiters back through foreground admission. An ordinary cache write failure can still deliver valid bytes to foreground waiters.

The worker polls conservatively and checks recent preview activity, free space on the thumbnail filesystem, cgroup memory headroom and changes in CPU throttling. The thresholds and fallback behavior are documented with the operating instructions. Pressure and offline scopes defer without consuming retries. Admin controls apply to this process and use configured scope numbers. Shutdown cancels discovery and allows five seconds after HTTP shutdown for the worker and its flight to drain. The timeout reports an incomplete shutdown and preserves the preview, ledger, index and caches until process exit. No frontend change is needed.
